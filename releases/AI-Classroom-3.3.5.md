## ⚠️ 关于安装包签名：原因与解决方法（必读）

### 原因

Android 有一条硬性规定：**新包与已装包的签名必须一致，否则拒绝覆盖安装**（报签名冲突），而签名不一致时**数据无法通过"更新"保留**——这是系统层的限制，任何安装器都绕不过去。

本项目历史上存在**两把签名钥匙**：

| 钥匙指纹（SHA-256 前 16 位） | 使用范围 |
|---|---|
| `4fffa5fb3b9e304d…` | **1.1.0 – 2.5.2** 全系（32 个 `ai-classroom-*-debug.apk`） |
| `07c9af654dc91a27…` | **3.0.0 – 3.3.0**（该期间改用过另一把钥匙） |

于是 3.0.0–3.3.0 期间，两拨用户互相升不上来：2.x 用户装不了 3.x，3.x 用户也装不了 2.x 的续作。

### 决定

- **自 3.3.5 起，恢复沿用 1.1.0 – 2.5.2 那把钥匙**（`4fffa5fb…`），让 2.0 系重新接上更新链。
- **3.0.0 – 3.3.0 停止维护**，不再作为主线。
- **Key B（`07c9af65…`）自本版起正式停止支持**：`3.0.0 – 3.3.0` 与 `AI-Classroom-3.3.5-legacy.apk` 不再接收任何后续更新，主包 `4fffa5fb…` 为唯一主线。

### 解决方法：按你装过的版本选包

**主包为修补版（`versionCode 39` / `3.3.5`），legacy 仍为 `versionCode 38` / `3.3.5`；除签名与上述修补外内容相同。** 选对包后**直接安装即可，数据由系统自动保留，不需要卸载、不需要备份还原**。

| 你手机上装的是 | 下载哪个包 |
|---|---|
| **1.1.0 – 2.5.2**（任何 `ai-classroom-*-debug.apk`） | **`AI-Classroom-3.3.5.apk`**（主包，`4fffa5fb…`） |
| **用 Android Studio「Run」跑出来的 debug 版** | **`AI-Classroom-3.3.5.apk`**（主包，`4fffa5fb…`） |
| **3.0.0 / 3.1.0 / 3.2.0 / 3.3.0**（GitHub 上的 `AI-Classroom-*.apk`） | **`AI-Classroom-3.3.5-legacy.apk`**（`07c9af65…`）— **已停止支持，仅作存档**；后续升级须按下方「Key B 迁移到 Key A」操作 |

> 怎么确认自己装的是哪一把？看你下载的文件名即可：`ai-classroom-*-debug.apk` → 主包；`AI-Classroom-3.x.x.apk` → legacy。
>
> 装错了会怎样？**只会报"签名冲突/无法安装"，不会丢失任何数据**——把对应的另一个包装上即可。

### Key B 迁移到 Key A（`3.0.0 – 3.3.0` 与 legacy 包用户必读）

**Key B 已停止支持**，主包是唯一主线。Android 不允许跨签名覆盖安装，所以迁移必然经过一次卸载，数据靠备份回填保住。以下流程已在本项目真机执行并校验通过：

1. **备份**（卸载前）：导出课堂数据
   - `files/ai_classroom_14_classes.json`（课堂、消息、配置）
   - `shared_prefs/ai_classroom_14.xml`（当前课堂索引、提示已读标记）
   - debug 版可直接 `adb pull`；release 版需 root（本机 `adb root` 已开启）
2. **卸载**：`adb uninstall com.aiclassroom.app`
3. **安装主包**：`adb install AI-Classroom-3.3.5.apk`
4. **回填**：把备份推回 `/data/user/0/com.aiclassroom.app/`，然后做两件必须的事——
   - `chown -R <新uid>:<新uid>`（卸载重装后 app uid **会变**，如本例 `u0_a264` → `u0_a299`）
   - `restorecon -R /data/user/0/com.aiclassroom.app`（修正 SELinux 上下文，否则应用读不到自己的文件）
5. **校验**：启动应用，课堂数量与对话内容一致，且无崩溃

> 不迁移的后果：停在 `3.3.5-legacy.apk` 仍可继续使用，但**永远收不到后续版本更新**（Android 硬规则，无绕过开关）。
>
> 多用户设备（如 MIUI 的「隐私空间 / security space」）需为每个用户分别执行；隐私空间须先由本人进入并解锁，`adbd` 无法代劳。

### 已在真机验证

在一台装着 `3.3.0`（`4fffa5fb…` 签名、`DEBUGGABLE`）的 Vivo V2454DA 上执行 `adb install -r`：

- 安装结果 **Success**，**全程未卸载**
- `firstInstallTime` 保持 `2026-06-29` 不变（证明是原地更新而非重装）
- 课堂数据文件 `ai_classroom_14_classes.json` **2,116,201 字节，修改时间分毫未动**

## 本次修补（3.3.5 修补版，versionCode 38 → 39）

`versionName` 仍为 3.3.5，`versionCode` 提升到 **39**，已装 3.3.5 的用户可直接覆盖安装，数据保留。

- **修复误报更新**：版本号此前硬编码在代码里（写死 3.3.0），导致装的是 3.3.5 却提示「发现新版本 3.3.5」。现改为读取构建产物里的真实版本号（`BuildConfig.VERSION_NAME`），不再与 `build.gradle.kts` 脱节。
- **修复弹窗无法滑动**：更新说明、更新提示、使用手册三处长文案此前被截断且不能滚动（整份内容塞进 LazyColumn 的单个 item），现改为可滚动容器，可上下滑动查看全文。
- **应用内说明同步**：`New!` 弹窗此前仍显示 3.3.0 的内容，现更新为 3.3.5 的实际改动。
