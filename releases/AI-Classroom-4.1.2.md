# AI Classroom 4.1.2

> 这一版的核心是**让进度真的不再丢**，以及**把生成成本降下来**。

---

## 彻底移除审查环节

审查原本对整节正文做 11 项检查（时间边界、性格漂移、重复桥段、越权知情…），发现问题就阻止提交并要求局部重写。设计意图是对的，但真机上完全不工作：

```
attempts: 16 次，最后一条 REVISING finish=Length len=0
审查返回内容长度 = 0
正文早已写够（1415 > 1250 目标），卡住的全是审查
```

三个问题叠加：审查返回空、修订被截断、修订失败后仍重新审查，形成「审查 → 修订 → 审查」的死循环。

**现在正文解析通过就提交。** 调用次数从 4~16 次降到 **2 次**（生成 + 状态提取）。

---

## 进度不再丢

这一版修了四个会让「进度看起来没了」的问题，全部有真机复现记录：

| 问题 | 原因 | 修复 |
|---|---|---|
| 上一节失败，下一节从头重写 | 输入指纹包含上游 `status` | 只比正文身份，上游真换版本才失效 |
| 中断重启后显示「待生成」 | 恢复时把有草稿的单元打回 PLANNED | 如实保留「已写 N 字」 |
| **每按一次生成，整本变「待重写」** | 自动同步无条件 `markReadyStale` | 只在设定真变了才标 |
| 写一节就把下游全标「待重写」 | 每次提交无条件传播 | 只有正文真的变了才传播 |

> 实测数据：vivo 上 22 条 run 记录里 19 条是 PAUSED，但**正文 268,108 字一个字都没丢**。丢的是「状态显示」，不是内容。

## 生成体验

- **每节独立「生成这节」**：只跑这一节，不必等整本排队，也不受别的节失败影响。
- **一节失败不再中断整轮**：记下原因、跳过它继续下一节，收尾时统一汇报。
- **每段预算改为「必须写满 N 字」**：原来写「建议约 800 字」，模型只写 230；也不再按失败次数缩小预算（那会越写越慢）。
- **分段上限按实测产出动态放宽**，硬上限 24 段。

---

## 界面

- **卡片布局**：每节一张卡片，边界清晰。
- **状态徽章**：已好 / 待重写 / 待保存 / 生成中 / 失败 / 待生成，颜色直接编码含义。
- **图标操作**：调整 ⚙ / 生成这节 ✨ / 阅读 📖，不再挤掉正文宽度。
- **长按删除课堂**：连同总纲、正文、草稿一起清理，二次确认。

---

## 人格与上下文

- **完整人格注入**：一致性规则、回复边界、公开背景、作者世界书、角色卡整段带进去，不再只搬 `mentorPrompt` 一句话。
- **第一人称**：以讲师视角写「我」，把对方称作「你」；对白独立成块。
- **来源对话改为「背景记忆」**：优先用记忆卡片（已总结的事实），退回原话时也用转述格式并去掉引号 —— 之前那种「我：… / 对方：…」的格式会被模型当成待续写的台词，直接搬进正文。

---

## 其他修复

- 状态提取补全 `SetRelationship` 的 `target` 与 `LearnFact` 的 `factId`；模型把角色名当 id 填时能映射，不再整份作废。
- 状态提取解析失败时带错误回灌重试一次。
- **网络中断不再自动重试**：必须用户点继续。以前 WorkManager 会在应用被杀、设备重启后自己接着跑，用户什么都没点却在烧额度。
- 每个项目只保留最近 8 条 run 记录，日志不再无限堆积。

---

## 已知限制

- 单节目标支持 1～20000 字。达到分段或调用预算仍不够时会停下并标记待处理，不会假装完成。
- 正文仍可能偶尔引用来源对话的原句。这是提示词层面的概率问题，没有做生成后扫描重写 —— 反复重写与速度直接冲突。
